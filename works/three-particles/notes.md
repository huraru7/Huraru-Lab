## できること

- モデル選択と粒子数の指定(左上の設定カード)
- 右上のボタンで元モデル表示と粒子表示の切り替え
- マウスドラッグでカメラを回転(操作していない間は自動で回転)

## 粒子化の仕組み

頂点同士をつなぐ面の描画を省略し、モデルの表面上にランダムに配置した点を
それぞれ1つの光る点として描き直している。面がなくなり点の集まりだけになる
ので、輪郭を保ったまま「粒子でできたモデル」のように見える。

粒子の配置には three.js の `MeshSurfaceSampler` を使っている。これは
三角形の面積が大きいほど選ばれやすい重み付き抽選で三角形を選び、その中の
ランダムな1点(重心座標)をサンプリングする仕組みで、結果として表面全体に
ほぼ均一な密度で点が散らばる。頂点そのものではなく面の上に点を置けるため、
粒子数はモデルの頂点数に縛られず自由に指定できる。

モデルが複数メッシュ(パーツ)からできている場合、パーツごとに面積比で
粒子数を配分してからサンプリングしている。面積の大きいパーツほど多くの
粒子が割り当てられ、パーツ間の密度差が出ないようにしている。

```
各メッシュ m_i のワールド座標での表面積を area_i とする
totalArea = Σ area_i

粒子数 target が与えられたとき、メッシュ m_i には
  round(target * area_i / totalArea) 個の粒子を割り当てる
  (端数の丸め誤差は最後のメッシュにまとめて吸収し、合計が target と一致するようにする)
```

サンプリングはランダムなので、同じ粒子数を指定しても「適用」を押すたびに
点の並び方は毎回変わる。

## カメラの合わせ方

モデルごとに大きさや中心位置が異なるため、表示するたびに全頂点を包む
最小の直方体を求め、その中心が画面の真ん中に来るよう全体をずらす。
カメラ距離は、直方体の縦幅・横幅それぞれが画面に収まる距離を三角関数で
別々に計算し、大きい方を採用する。

```
vFov = カメラの縦視野角 (ラジアン)
hFov = 2 * atan( tan(vFov / 2) * アスペクト比 )

距離(縦) = (モデルの高さ / 2) / tan(vFov / 2)
距離(横) = (モデルの幅   / 2) / tan(hFov / 2)

採用する距離 = max(距離(縦), 距離(横)) * 余白係数
```

対角線の長さだけで距離を決めていた最初の実装では、横に広い・平たい形状で
上下が画面から欠けた。縦横を別計算にして解決している。

## 質感とライティング

金属のように反射するマテリアルは、周囲の景色が映り込むことで質感が出る。
何もない黒い空間では映り込む景色がなく、画面全体がほぼ黒くなってしまうため、
部屋のような架空の空間を簡易的に作ってモデルの周りに映り込ませている。

## 踏んだバグ

> **① モデル切り替えで位置ズレが蓄積する**
>
> - 症状: モデルを切り替えるたびに表示だけが少しずつずれていく
> - 原因: 位置をリセットした直後は、まだ描画が1度も行われていないため、「現在の変換結果」を内部で保持している値は前のモデルを中心に置いたときの古い数値のまま。中心座標を求める計算がこの古い値を参照してしまい、次のモデルの正しい位置に前のズレがそのまま上乗せされていた
> - 対処: リセットの直後に変換結果を強制的に反映させてから、次の計算に進むよう順序を変更
>
> ```
> 位置 = (0, 0, 0)          // リセットしただけでは反映されない
> 変換結果を強制的に更新       // ← この一手間が抜けていた
> 中心座標を計算 → ズレなし
> ```

> **② 一覧ページのプレビューで設定パネルが被る**
>
> - 症状: ラボの一覧ページに小さく埋め込んだプレビューで、操作用の設定パネルが表示を覆い隠す
> - 原因: 単独ページでも一覧の小窓でも、同じUIを無条件に表示していた
> - 対処: 「一覧ページの中に埋め込まれているか」を判定し、埋め込み時だけ操作パネルを非表示にした

> **③ 粒子数を変更するたびに粒子だけ位置がずれる**
>
> - 症状: モデル読み込み直後の粒子表示は正しいのに、粒子数の設定を変えて「適用」を押すと元モデルと粒子の位置がずれる(特に縦方向)
> - 原因: 各メッシュの面サンプリング結果をワールド座標に変換する際、メッシュの変換行列を参照(≒ポインタ)のまま保持していた。中心合わせのために全体を動かした後、1回でも描画が走ると参照先の行列の中身が新しい位置に書き換わってしまうため、後から粒子を作り直すと「中心合わせ後の位置」を「中心合わせ後の位置に置き直す」ことになり、ズレが二重に乗ってしまっていた
> - 対処: メッシュ収集の時点で変換行列を複製して固定値として持たせ、後から中身が変わらないようにした

## 気づき

- 「画面上は正しく動いて見える」ことは、内部の計算が正しい証拠にはならない。2つの誤差が打ち消し合っていると、片方だけ直したときに逆に見た目が崩れることがある
- モデルごとに大きさや中心位置が異なるため、カメラ距離や粒子サイズを固定値で決め打ちすると別モデルで簡単に破綻する。表示のたびに毎回測り直す作りにしておいたのが結果的に正解だった
