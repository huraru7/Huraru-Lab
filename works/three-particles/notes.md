## 粒子化の仕組み

頂点同士をつなぐ面の描画を省略し、モデルの表面上に点として描き直している。
面がなくなり点の集まりだけになるので、輪郭を保ったまま粒子でできたようなモデルに見せる。

粒子の配置にはthree.jsの`MeshSurfaceSampler`を使用し。
三角形の面積が大きいほど選ばれやすい重み付き抽選で三角形を選び、その中の
ランダムな1点をサンプリングすることで表面全体にほぼ均一な密度で点が散らばるように描画する。頂点そのものではなく面の上に点を置けるため、粒子数はモデルの頂点数に縛られず自由に指定できる。

モデルが複数メッシュの場合はパーツごとに面積比で粒子数を割合で分配してサンプリングする。

```
各メッシュ m_i のワールド座標での表面積を area_i とする
totalArea = Σ area_i

粒子数に対してメッシュ m_i には
  round(target * area_i / totalArea) 個の粒子を割り当てる
  端数の丸め誤差は最後のメッシュにまとめて吸収し、合計が target と一致するようにする
```

サンプリングはランダムなので、同じ粒子数を指定しても更新するたびに点の並び方は毎回変わる。

## カメラの合わせ方

モデルごとに大きさや中心位置が異なるため、表示するたびに全頂点を包む
最小の直方体を求め、その中心が画面の真ん中に来るよう全体をずらす。

```
vFov = カメラの縦視野角(ラジアン)
hFov = 2 * atan(tan(vFov / 2) * アスペクト比)

距離(縦) = (モデルの高さ / 2) / tan(vFov / 2)
距離(横) = (モデルの幅 / 2) / tan(hFov / 2)

採用する距離 = max(距離(縦) , 距離(横)) * 余白係数
```

対角線の長さだけで距離を決めていた最初の実装では、横に広い・平たい形状で
上下が画面から欠けた。縦横を別計算にして解決している。

## 質感とライティング

金属のように反射するマテリアルは、周囲の景色が映り込むことで質感が出る。
何もない黒い空間では映り込む景色がなく、画面全体がほぼ黒くなってしまうため、
部屋のような架空の空間を簡易的に作ってモデルの周りに映り込ませている。

## 踏んだバグ

> **① モデル切り替えで位置ズレが蓄積する**
>
> - 症状: モデルを切り替えるたびに表示だけが少しずつずれていく。
> - 原因: 位置をリセットした直後、現在の変換結果を内部で保持している値は前のモデルを中心に置いたときの古い数値のままになっていることで中心座標を求める計算がこの古い値を参照してしまい、次のモデルの正しい位置に前のズレが上乗せされて描画されていた。
> - 対処: リセット後に変換結果を強制的に反映させてから、次の計算に進むように変更。
>
> ```
> 位置 = (0, 0, 0)          // リセットしただけでは反映されない
> 変換結果を強制的に更新       // ← この一手間が抜けていた
> 中心座標を計算 → ズレなし
> ```

> **② 粒子数を変更するたびに粒子だけ位置がずれる**
>
> - 症状: モデルの粒子数の設定を変えて適用を押すと元モデルと粒子の位置がずれる。
> - 原因: 各メッシュの面サンプリング結果をワールド座標に変換する際、メッシュの変換行列を参照のまま保持していた。中心合わせのために全体を動かした後、1回でも描画が走ると参照先の行列の中身が新しい位置に書き換わってしまうため、後から粒子を作り直すと中心合わせ後の位置を中心合わせ後の位置に置き直すことになり、ズレが二重に乗ってしまっていた。
> - 対処: メッシュ収集の時点で変換行列を複製して固定値として持たせ、後から中身が変わらないようにした。
